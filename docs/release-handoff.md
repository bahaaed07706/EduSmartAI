## Architecture

```
React static bundle  ──HTTPS──>  FastAPI web service  ──>  PostgreSQL (managed)
     (Vercel)                     (Render)             ──>  Persistent disk (uploads)
```

The backend needs a persistent server because it writes to a database and an
uploads directory on every request and holds a 14.3 MB model resident;
serverless would lose writes between invocations. The frontend is a static
bundle, so it belongs on a CDN. Reasoning in
[deployment-decision.md](deployment-decision.md).

Config lives in `render.yaml` (backend, database, disk) and
`edusmartai-frontend/vercel.json` (frontend).

## Deployment procedure

**Order matters:** deploy the backend first, because the frontend needs its URL,
and then set CORS to the frontend's URL once it exists.

0. **Rotate credentials first.** The demo passwords committed earlier are in git
   history and in any database seeded with them. Treat as compromised.

**Backend — Render**

1. Render → New → Blueprint → connect `bahaaed07706/EduSmartAI`.
2. Render reads `render.yaml` and provisions the Postgres database and the API
   service with its 1 GB disk.
3. Set the variables marked `sync: false` (listed below).
4. First deploy runs `python migrate_schema.py`, then starts uvicorn.
5. Seed synthetic demo data once: `python seed_data.py` from the service shell.
6. Verify `/ready` returns 200 with `database: true` and `models: true`.

**Frontend — Vercel**

7. Vercel → Add New Project → import `bahaaed07706/EduSmartAI`.
8. Set **Root Directory** to `edusmartai-frontend`. Vercel then picks up
   `vercel.json` (CRA preset, SPA rewrites, security headers, immutable caching
   on hashed assets).
9. Set `REACT_APP_API_BASE_URL` to the Render service origin — no trailing
   slash, no path; the client appends `/api/v1` itself.
10. Optionally set the `REACT_APP_DEMO_*` variables to surface demo logins.
11. Deploy.

**Connect the two**

12. Back in Render, set `CORS_ORIGINS` to the exact Vercel production origin and
    redeploy the API. The app refuses to boot in production on a wildcard.
13. Confirm a login works end to end from the Vercel URL in a clean browser.

## Environment variables

**Backend** — set in Render:

| Variable | Notes |
|---|---|
| `DATABASE_URL` | From the managed database. `postgres://` is normalised automatically |
| `JWT_SECRET` | Generated by Render. Nobody needs to see it |
| `CORS_ORIGINS` | Exact frontend origin. A wildcard makes the app refuse to boot in production |
| `ENVIRONMENT` | `production` — disables API docs, enables HSTS |
| `UPLOAD_DIR` | `/var/data/uploads`, the mounted disk |
| `MODELS_DIR` | `../Saved_Models` |
| `GROQ_API_KEY` | Optional. Without it the chatbot uses its local fallback and reports `ai_powered: false` |
| `SEED_ADMIN_PASSWORD` | 12+ chars. No default — seeding fails without it |
| `SEED_LECTURER_PASSWORD` | 12+ chars |
| `SEED_STUDENT_PASSWORD` | 12+ chars |

**Frontend:**

| Variable | Notes |
|---|---|
| `REACT_APP_API_BASE_URL` | API origin, no trailing slash and no path |
| `REACT_APP_DEMO_STUDENT_EMAIL` / `_PASSWORD` | Optional. Shown on the login screen |
| `REACT_APP_DEMO_LECTURER_EMAIL` / `_PASSWORD` | Optional |

There is deliberately no admin demo variable. An evaluator does not need
destructive access, and publishing an admin password is how the previous
credential leak happened.

## Commands

```bash
# Migrate (additive and idempotent; safe to re-run)
python migrate_schema.py

# Seed — fresh databases only, never over existing data
python seed_data.py

# Run
uvicorn main:app --host 0.0.0.0 --port $PORT

# Verify
curl https://<api>/health     # liveness
curl https://<api>/ready      # database + models

# Tests
cd backend && python -m pytest -q          # expect 103 passed
cd backend && python -m ruff check .
cd edusmartai-frontend && CI=true npm run build

# Audits (need both servers running and credentials in the environment)
node scripts/a11y-audit.js         # expect 0 violations
node scripts/responsive-audit.js   # expect 0 issues
```

## Backup and restore

PostgreSQL: use the platform's managed backups; verify a restore into a
disposable database before relying on them.

Uploads: the mounted disk is not backed up by default. Until object storage
lands (roadmap item 4), snapshot it on the same schedule as the database — the
two must be restored together, since a submission row without its file is a
broken record.

**Never** restore a production database over the local `backend/edusmart.db`.

## Rollback

PR #1 is merged (`0639a12`). To roll it back:

```bash
git revert -m 1 0639a12
```

No migration is destructive — additive `ALTER TABLE ADD COLUMN` only — so a
revert needs no data restoration. Redeploy the previous Render deploy from the
dashboard for an immediate rollback while the revert propagates.

## Maintenance

- Re-run both audit scripts after any layout change. They exit non-zero, so they
  work in a pipeline.
- Re-run `scripts/evaluate_models.py` if a model is ever retrained; it is
  read-only and will not modify artifacts.
- Watch `quill`/`react-quill` for a non-breaking fix to the last two advisories.
- The rate limiter is per-instance and resets on restart. If the service is
  scaled beyond one instance, move it to a shared store — otherwise the limit
  multiplies by replica count.

## Known limitations

1. Not deployed. Architecture decided, configuration committed, execution pending.
2. PostgreSQL support is implemented but has never run against a real instance;
   the test suite uses SQLite.
3. OULAD accuracy (0.9790) is inflated by target leakage and unusable for early
   prediction.
4. LLM answer quality unverified — no API key has been available.
5. RAG evaluation set is 12 queries; the abstention threshold was calibrated on
   that same set.
6. Accessibility covers 6 of 37 pages.
7. RTL is partial — logical properties are in place, no language switcher.
8. Two moderate advisories in `quill`/`react-quill`.
9. Previously committed demo passwords remain in git history and must be rotated.
